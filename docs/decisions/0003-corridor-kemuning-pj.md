# 0003 — Phase 1 corridor is Kota Kemuning ↔ PJ via KESAS + LDP

- Status: accepted · 2026-11-22
- Context: The original corridor (Federal Highway, Shah Alam ↔ KL) had approximate, unverified gates; a check on real OSM data showed the west gate snapped to a side street (Jalan Majlis) and capped max flow at 1,800 veh/h. The owner knows the Kota Kemuning → PJ commute (KESAS then LDP) first-hand, which makes the validation gate (docs/validation.md) checkable.
- Decision: Replace the Phase 1 corridor with `kemuning-pj`: gates on KESAS (E5) at exit 506B Kota Kemuning and LDP (E11) at exit 1108 Taman Megah; bbox [101.50, 2.98, 101.66, 3.14] to include parallel routes (Federal Highway, NPE, Subang, Puchong). Still one corridor; the "more corridors" non-goal is unchanged. Fetching moves to the Overpass API by default (Geofabrik remains as `OSM_SOURCE=geofabrik`).
- Findings at decision time (placeholder capacities, 2026-11-22 OSM): on the KESAS → Sunway → LDP route alone, the bottleneck is the 1-lane ramp at Sunway (exit 511A, way 31657409, 2,000 veh/h, lanes tagged). Over the whole network, flow (6,000 veh/h) is capped by KESAS itself at the source gate, because drivers can bypass the ramp via Kewajipan (exit 510) → NPE → LDP.
- Consequences: With single-road gates the whole-network min cut will often be the gate road itself. cmd/analyze must snap gates per carriageway (ARCHITECTURE §3.3). A "fixed route only" analysis is not in Phase 1 (close to the route-choice non-goal); revisit if the whole-network result is uninformative. `config/corridors/federal-highway.json` is kept only for reference and is not used.
